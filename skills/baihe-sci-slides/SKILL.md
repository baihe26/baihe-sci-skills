# baihe-sci-slides · 科研汇报


适合已有图和已确认内容的科研汇报；不要把排版任务擅自扩大为新统计或重新解释结果。使用已配置Live PowerPoint Studio及其现有后端。V03为默认作者风格，内容决定布局，不作为固定模板；其他风格按明确要求选择，不自动升级版本。

0.6支持只读项目接入与图号使用/未用原因记录；新增风格侧件只记录profile身份、版本、来源哈希与局部覆盖范围，不自动应用新主题或继承作者接受。可对最终PPTX执行目标到实际对象核对；后处理之后重查相应最终文件，旧阶段PASS不能自动传递。面板候选和有效字号检查仍须整页视觉复核。按需读`文档/0.6升级与验收.md`。

入口为 `baihe-sci.cmd --module ppt --manifest <宿主整理的manifest> --mode FAST`；需现场渐进制作可选LIVE。原生API由现有后端提供，不新建竞争COM服务，不调用会改注册表的旧guard。

保留科学配色、坐标、图注和来源。外层文字用原生对象；源Origin图作为图片时保留OPJU编辑路径，不宣称其成为PPT原生数据图；嵌入SVG不等于可逐对象编辑的原生图。

按真实插入尺寸检查字体、图例、误差和点的可见性。空间不足时制作科学语义等价的显示副本或拆页；不改n、误差、分母和科学绑定。稳定slide/object/asset/revision ID与原生指纹用于总稿/小稿定向更新。原生指纹变更或human override保留为冲突，不能盲覆盖人工版本。

只改指定文字/位置/颜色时另存revision，比较无关对象。照片和视频核对字节，视频还需实际播放；SVG字节不同需另验视觉，不能直接断言损坏或无损。保存重开后检查原生对象、媒体、整页渲染与恢复Journal。视觉复核优先只读独立检查，原生软件保持单写者。不默认批量导出PDF。最终作者科学与审美接受由本人确认。

可选python-pptx路线属于vector图件生产；0.4可组装已批准同尺寸多页图件并共用原生Tags，仍不替代本技能的Live Studio/V03内容组织与媒体流程。需要无Office图件时按该子技能明确选择，不能静默切换整个汇报后端。当前CLI自动保留阶段与输出哈希；`--status`只读对账人工变更，`--compare-images`输出环境绑定的差异报告。

0.4提供保存文件的`--reference-index`与`--propagate`薄接口，可同时定位总稿/小稿中的标准Tags图片引用；人工差异包括图片本身、裁剪、分组变换与覆盖标记，冲突位置保留。只修改新副本中的选中引用，其他媒体字节保留；新图片不能继承旧像素的来源证明，须核对新来源。它不观察软件中的未保存编辑，不替代原生重开与整页验收。可选多页图件只消费已批准SceneGraph，不替代V03的内容组织。按需读`文档/证据与引用操作.md`。


0.5公开仓库已含配套源码。首次环境准备读取根目录“文档/0.5公开配套与自动安装.md”，使用“安装与检查.cmd”自动准备D盘独立Python与锁定依赖；不要沿用“私有引擎未提供”的旧结论。具体任务仍用“baihe-sci.cmd”与本机配置；商业软件、版本门禁、科学合同与逐模块原生验收保持原边界。
