# 论文排图与交付改良

这些接口复用现有工作台；通用科研汇报、V03、原生 Tags、人工冲突保护和媒体流程继续可用。新增设置只影响明确启用的任务，不把某个项目的字号、材料名称或图号写成默认规定。

## 按内容分配版面

`project_intake.panel_candidates(manifest_path, out)` 原来的 `layout_columns` 行为保留。需要主次与跨行跨列时，在同一 `project-intake-0.1` 清单加 `layout_variants`：

```json
{
  "layout_variants": [{
    "id": "重点谱图与局部",
    "columns": [3, 1],
    "rows": [1, 1],
    "placements": [
      {"panel_id": "spectrum", "row": 0, "column": 0, "row_span": 2},
      {"panel_id": "photo", "row": 0, "column": 1},
      {"panel_id": "statistics", "row": 1, "column": 1}
    ]
  }]
}
```

行列数组是相对权重。每个小图恰好出现一次；单元不得相交。保留局部时用 `preserve_bbox_mm: [左, 上, 右, 下]` 和 `preservation_source` 记录人工父本中的位置。位置保留仍需保持图像比例，不允许用变形掩盖位置冲突。小图可声明 `minimum_width_mm`、`minimum_height_mm`、`aspect_range`。源像素、显微标定和裁剪确认沿用原有检查。

布局候选不会自动给出审美接受。它只生成布局记录和框线预览，不修改来源图。素材的内容权重由作者/宿主确定，程序不按文件名猜哪个实验重要。

## 检查真正保存的 PPT

`delivery_review.audit_presentation(artifact, profile=None, out=None)` 读取实际文件。它计算嵌套组合的几何缩放、平移、旋转和镜像；读取常见的段落、形状、版式、母版和演示文稿字号继承。输出每段文字的工作字号、几何估计、继承来源以及每个对象的位置。**组合框缩为一半不证明字形字号也减半。** 本轮 PowerPoint 原生导出已发现 18 pt 组合文字在框缩小后仍约为 18 pt，旧的 `18 × 0.5 = 9` 结论已撤回。组合或自动适配文字的 `effective_pt` 保持未知，仅给 `geometric_estimate_pt`，要求原生校准，不能凭估计给字号 PASS/FAIL。整页按目标物理宽度插入的缩放单独计算；普通未组合文字可按已声明字号计算这一外层比例。未知继承保留待核，不猜一个默认字号。

按需传入本轮作者设置，例如：

```json
{
  "minimum_effective_font_pt": 8,
  "required_font_family": "Aptos",
  "target_width_mm": 180,
  "intentional_overlaps": [
    {"object_ids": ["inset_caption", "inset_background"], "reason": "已核对的有意叠放"}
  ]
}
```

这些数字和字体只是接口示例，不是期刊规定。没有传入的偏好不会自行启用。上下标由 OOXML baseline 识别，不作为新的正文工作字号档。非等比组合会标为需看实际渲染，因为仅凭对象尺寸不能证明字形没有被拉伸。字体家族检查目前读取 run/段落的显式声明；主题继承未知或实际缺字回退仍需看原生渲染，不把字体声明当实际字形证明。

检查可以提示后置图片/不透明填充可能盖住文字，并给出页码、双方对象名、文字框受影响比例。**这是变换后对象框和层叠顺序检查，不是文字字形识别。** 图像透明区、非矩形轮廓、抗锯齿与视觉效果仍需看最终导出。没有自动发现问题也不等于视觉通过。

既有 `verify_delivery` 新增 `kind: "effective_min_font_pt"`，只对有可用尺寸依据的具体对象检查；组合/自动适配未经原生校准时返回待核。旧 `min_font_pt` 继续检查工作字号，并能读取明确的字号继承，避免把两种含义混在一起。

## 给作者能直接讲的备注

`delivery_package.format_panel_notes(panel, sources, page_offset=None)` 使用已核实字段组织句子，不自动推断实验结论。一个小图提供：

```json
{
  "id": "ftir", "label": "c", "title": "各材料红外光谱",
  "meaning": "比较复合前后的特征吸收",
  "source_ids": ["summary", "raw"],
  "processing": "保留完整有效谱点重绘，调整字体和排布"
}
```

来源列表分别使用以下 `kind`：

- `summary_ppt`：`title`、`version`、原 `page`、`page_description`。实际写备注时还需 `source_pptx: {path, sha256}` 绑定原文件，可用 `object_ids` 指定原页中的对象名称。程序读取实际原页对象/媒体签名，核对对象存在。没有原页标题可描述实际页内容。`page_offset` 可为空、整数或本轮指定符号，原页码本身不变。
- `raw_data`、`derived_data`、`source_project`：`display_path` 或相对 `path`，可补工作表/列等 `locator`。给读者的路径不能出现完整盘符路径；绝对路径需提供适当的 `display_root` 才能裁为相对位置。
- `thesis`：`relationship` 为 `same_data`、`related_only`、`not_found` 或 `not_checked`。前两种需 `title` 与 `locator`，不把“相关实验”写成“同一数据”。

没有上游汇总 PPT 的一般项目，直接写原表/派生表来源，不要求解释一个不存在的汇总。只有显式声明 `summary_context: "specified_summary_missing"`，才要求 `absence_from_summary_reason`，说明指定汇总为何没有此项。来源文件能否证明实验含义仍需核对；句子生成不等于科学解释。

`delivery_package.write_notes(request_path, out)` 可以写到新 PPTX 副本。请求包含 `artifact: {path, sha256}`、上述 `sources`、`panels`，以及 `slides: [{slide_index, panel_ids, expected_notes}]`。按小图顺序组合备注。`expected_notes` 即使为空也必须与当前值完全匹配，保护作者手动清空的备注。尚无备注部件时也可显式 `allow_new_notes: true` 创建；有现存空备注不能借此绕过。输入须符合当前任务上下文的人工父本或已核派生关系。本接口只更新备注相关部件，幻灯片 XML、图像、图表和嵌入工程的原字节保留；未选页备注保留。保存后重新读取核对文本。它没有替代原生 PowerPoint 重开和最终人工阅读。

备注与资料包可共同引用 `source_catalog: {path, sha256}`；该文件为 `delivery-source-catalog-0.1`，保存同一份 `sources`。启用它后不再另填一份 `sources`，避免互相覆盖。备注记录保存每项来源文件、版本、原页码、对象和页内容签名；包中 `source_pages` 用同一 `source_id` 解析这些字段。包的 `notes_records: [{file_id, deck_file_id}]` 把备注记录和当前 PPT 绑定，会发现备注用 v1 第 7 页、包却用 v2 第 4 页的冲突。说明文字仍由已核事实提供，不从图片猜科研结论。

需要验收完整备注时，设置 `requires_notes_binding: true`，并按不同交付版本登记具体范围，例如 `notes_requirements: [{deck_file_id: "presentation_deck", slides: [{slide_index: 2, panel_ids: ["ftir", "xrd"]}]}]`。每条生成记录保存 `slides[].panel_notes` 的逐小图实际文字；核对时既比较当前页真实备注，也核对这些文字块和要求的小图顺序/位置。空 `slides`、空备注、漏页、把说明写在另一页都不能算覆盖完成。若同一包内两版 PPT 使用不同小图集合，分别登记范围，不把全包所有小图强塞进每版。已有稳定 PPT 小图对象位置也可用于推导页码；没有明确范围或实际对象对应时保留待核，不从一份来源记录推断备注已完整。没有备注交付要求的项目无需启用这些字段。

## 交付包校验

`delivery_package.verify_package(manifest_path, out=None)` 使用 `research-delivery-0.1` 清单，限定在明确的 `package_root` 内。文件表用 `id`、包内相对 `path`、`sha256` 绑定本版。小图表用稳定 `id`、`figure_id`、`destination`（`main` / `supplement` / `reserve` / `excluded`）和按角色划分的 `files` 对应文件 ID。示例：

```json
{
  "schema_version": "research-delivery-0.1",
  "package_root": "交付包",
  "expected_panel_ids": ["ftir"],
  "required_roles": ["raw_data", "current_project", "final_figure"],
  "files": [
    {"id": "raw", "path": "图2/c/原始数据/谱表.csv", "sha256": "实际文件哈希"},
    {"id": "project", "path": "图2/c/当前工程.opju", "sha256": "实际文件哈希"},
    {"id": "figure", "path": "图2/c/当前图.svg", "sha256": "实际文件哈希"}
  ],
  "panels": [{
    "id": "ftir", "figure_id": "F2", "destination": "main",
    "files": {"raw_data": ["raw"], "current_project": ["project"], "final_figure": ["figure"]}
  }]
}
```

`required_roles` 来自本轮交付要求，也可由单个小图覆盖；不存在适用原始数组的纯示意图不应被强制要求实验 CSV。退出正文仍应有补充、备用或明确排除去向，排除必须写原因和授权。可声明 `figures` 的小图集合，验证前后成员记录一致。

原始副本可填 `original_source: {path, sha256}`，会核对原件内容、原名和修改时间；不把派生工程伪装成历史原件。`source_pages` 记录来源页副本 `file_id`、`source_version`、`original_page` 和可选 `page_in_copy`，检查它是可打开且页码存在的 PPTX。当前图在两个包中应相同的，可用 `synchronized_pairs` 声明文件 ID 对。`audit_unlisted_files` 可发现未登记的旧版本，程序不会自行删除。

在每个 `source_pages` 中再提供 `source_pptx: {path, sha256}`，会直接读取原汇总的 `original_page` 和包内副本的 `page_in_copy`，比较实际页面对象、文字以及被引用的媒体/嵌入内容。关系 ID 或 ZIP 部件名变化不会单独被当成内容变化。错页虽然能打开，也会报出具体小图不对应；缺少原汇总证据时保留“原页内容未核对”，不把页码存在当内容已匹配。版式、母版、主题导致的显示变化仍需查看实际导出。

存在当前工程却缺少曲线/导出对应证据时，返回 `PACKAGE_BINDINGS_PENDING` 并明确指出具体工程，不再给记录齐全的笼统通过。小图的 `project_bindings` 可关联 `project_file_id`、`final_file_id`、`evidence_file_id`；证据使用原生工作流生成的 `native-plot-binding-0.1`，核对工程版本、实际导出图、原始/派生表哈希及原生数组/图窗反读状态。没有实际反读的生成记录保持待核。它不能根据 OPJU 扩展名证明可编辑性，也不能把人工填写的证据冒充原生实测。

声明 `current_presentation_file_ids` 后，主图/补充图的 `presentation_occurrences` 通过 `deck_file_id`、稳定 `slide_id`、`object_id` 和 `final_file_id` 对应当前 PPT 对象。程序读取该对象实际图片字节，与包内最终图比较；同一页旧图片、误绑其它小图会报冲突。若大图已被压平而没有可追踪小图对象，应保留待核或使用适合该成品的实际核验，不能虚造对象记录。

此校验能发现漏文件、旧版本、漏小图、外部依赖和同名混淆，**不能只凭哈希证明 Origin 曲线确实绑定了对应实验**。原生图窗/工作表/数组、显微显示变换与可编辑动作应另有直接证据。没有证据时报告具体哪一项未核，不输出全包“已无误”。

## 本轮验证范围

合成回归覆盖：组合缩放的字号估计不能冒充实测、段落继承、旋转/自动适配/整页插入的不同处理、后置照片遮字母、偏好不污染通用任务、权重与固定位置、不同来源类型的自然语言备注、人工清空备注冲突、无汇总项目、来源跨版本页码一致性、未选页与原媒体保留、包内旧文件/漏小图/外部路径、当前 PPT 真实媒体绑定和未授权排除。验证真实保存的 PPTX 和配套文件；没有用私有研究材料做公开测试。原生软件重开、屏幕/纸面视觉、实验正确性、作者最终接受分别记录，不能沿自动测试结果扩大宣称。

独立审后用新合成文件完成 PowerPoint 只读重开、原生 PNG 导出、文字与来源备注反读；输入文件哈希未变。相同句子放置原生 9 pt、18 pt、组合框缩半的 18 pt、旋转 18 pt 和 `normAutofit=0.5` 五种情形。原生读回及图面都显示：本例组合文字仍为 18 pt，自动适配文字为 9 pt；旋转没有改变声明字号。已用同页参考字形比较，而非把测试页写的数字当证据。这只校准该合成情形，不据此普遍认定任意组合/主题/编辑历史的实际字号。

另用本轮真实 Origin 生成、修订且独立重开的合成 OPJU、实际 PNG、CSV 和原生绑定记录组成资料包，再与当前 PPT 的实际图片对象绑定。正例对应记录通过，PPT 已原生重开与导出查看。反例换入同次流程早期的真实 OPJU，并同步更新其文件登记哈希，仍被工程—导出绑定识别为旧工程。该原生证据直接覆盖所声明主曲线的 X/Y 与数组；误差附属 plot 未在这份记录中单独反读，不能把本例扩成全部误差绑定或所有模板原生通过。
