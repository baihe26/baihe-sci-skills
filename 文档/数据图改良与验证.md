# 数据图接入、修订与验证

本轮保留原合成 Phase2C 入口及已配置绘图工位。新增正常真实表入口，把源数据映射检查、当前项目显示参数和原生运行接在一起；既有 Origin 工程也可按图窗/工作表/曲线身份做局部副本修改。此模块不会从实验图像或列名自动认定科学结论。

## 三条入口

- 原合成基线：`--module plot --bundle <合同目录>`，原合同与既有验收不变。
- 核对来源：`--plot-task <任务记录.json> --out <新目录>`。真实文件读取、数组/变换/组别映射与实际活动引擎准备计划核对，不激活 Origin。
- 执行：在前一条加入 `--execute-plot`。`render_table` 通过当前配置的 EditaPlot 原生 renderer 生产；`revise_origin` 对已确认父工程新存，修改文字位置/字号、刻度字号、绑定曲线线宽，再由独立进程重开读回。

命令使用宿主从当前已授权任务整理的记录，不要求作者重新批准已授权的显示修改。不支持的局部改动交现有 Origin 原生工具；新入口不覆盖全部商业软件能力，也不把只登记来源说成改完。

协调入口会把 `--plot-task` 转交当前配置的 `plot_python` 执行接入核验及绘图流程，再由 `origin_python` 执行原生操作。这样保留已有绘图依赖，不要求 Office 协调环境再安装一套绘图包；配置缺失时报告具体缺项，不换用其它环境或升级共享依赖。

## 最小任务记录

以下仅演示格式，数值和名称均为合成例。`sha256` 由宿主对实际文件计算；相对路径以任务记录所在目录为基准。

```json
{
  "schema_version": "plot-task-1",
  "task_id": "当前图谱修订",
  "operation": "render_table",
  "authorization": "作者本轮要求从已确认表出图",
  "plot_type": "continuous_spectrum",
  "render_table": {"path": "显示表.csv", "sha256": "文件实际校验值"},
  "backend": {
    "template_id": "ftir",
    "column_mapping": {
      "assignments": {"Wavenumber": "x", "Signal": "series"},
      "plot_mode": "overlay"
    }
  },
  "physical_style": {
    "page_width_cm": 10,
    "page_height_cm": 8,
    "axis_title_size_pt": 12,
    "tick_label_size_pt": 10,
    "legend_size_pt": 10,
    "plot_line_width_pt": 1.2
  },
  "curves": [{
    "id": "稳定曲线身份",
    "group_id": "sample_A",
    "display_label": "Material A",
    "identity_basis": {"path": "已确认身份.txt", "sha256": "文件实际校验值"},
    "source": {"table": {"path": "原表.csv", "sha256": "文件实际校验值"}, "x": "Wavenumber", "y": "Signal"},
    "display": {"table": {"path": "显示表.csv", "sha256": "文件实际校验值"}, "x": "Wavenumber", "y": "Signal"}
  }]
}
```

这些尺寸仅是格式示例，不能写为所有稿件的固定规则。`physical_style` 将受支持的物理尺寸、字号、线宽、图层边界传给当前活动引擎的 preparation，并计入其计划摘要。未声明的字段沿用该模板兼容默认，不声称默认满足任意最终尺寸。曲线显示名从明确的原列—组别映射得到，原工作表列值不变。

有依据的轴标题用 `axis_titles` 逐轴给出 title、reason、evidence 文件引用；普通科学表沿用已存在的文字覆盖接口。XPS 标题仍由确认的能量类型计划产生，不接收仅改能标标题。科学表可沿用已注册 `backend.palette_id`，精确科学色映射超出当前原生适配的，不能假称已应用。

源表可为 CSV/TSV/TXT/XLS/XLSX；表格明确工作表和表头行。公式表须提供保留原件的核对数值导出。原生绘图输入目前使用透明的首行为列名 CSV，所有实际绘制列必须有来源映射，不能在核对时只取前几行而生产全表。若已有 Origin 图，只登记 OPJU 不等于已经检查内部：`origin_binding` 还要给出 graph、worksheet、x_column、y_column、rows、layer、plot_index。当前可执行局部路线核对完整列，分段绑定需专用适配。

```json
{
  "kind": "label",
  "graph": "Graph1",
  "layer": 1,
  "name": "yl",
  "values": {"left": 35, "top": 90, "fsize": 12}
}
```

`native_edits` 可包含这种标签位置/字号修改；`axis_tick_font` 使用 axis 与 font_pt；`curve_width` 使用已登记 curve_id 和 line_width_pt。位置属于原生页面坐标，应从实际图面读回决定，不能复制例子。不会开放任意脚本或自动改数据。输出原件哈希、全部工作表/矩阵一致性、实际曲线 X/Y 绑定、编辑读回和独立重开记录。

## 已解决的返工风险

1. 不再仅凭点数认定同一数据：逐值检查源列与当前显示列，记录行范围、排除原因和缺失段。显示抽稀要求完整原生曲线及端点/极值/指定特征/缺失段得到保留。
2. 换单位需要数值变换与依据；换能标需要明确光子能量及参考零点约定。不能默认所有仪器都另扣同一功函数。现行 XPS `prepare_xps` 本来已区分两种能标，本次修旧文档/旧接口风险，不指控历史图一概错误。
3. 连续谱采样点符号、图例与线型/点型不符、线样像下划线、误差/星号无来源，会被任务检查定位。它检查提供的对象记录，不能代替实际图面视觉。
4. 直方图按明确分箱和原数值核对，不能减少柱数却仍称同一个统计图；误差、n 和筛选规则没有一套跨项目固定值。
5. 新路线保留有用的旧原生绘制器、队列和 owned session；宿主共同单写者锁在父进程，旧 Origin 队列锁在 worker 内，各取一次，不互相递归占有。

## 活动路线与随包模板

此仓库不覆盖用户已配置的外部引擎，也不自动改其补丁。新版 `plot_sources.py`、`plot_runtime.py` 和 `plot_native_worker.py` 从当前本机配置加载引擎，新增源数组、显式显示名和物理样式就在这一正常路线生效。随包 XPS/FTIR/柱图/误差图模板文案同步纠正旧的“遮挡留给用户”和大字号死规则；直接调用旧外部模板时不会自动继承这些文案更新，应走新任务入口或由维护者定向升级。

## 验证边界

`tests/test_plot_regressions.py` 的脱敏合成用例复现点数变少、同点数错列、抹平窄峰、单位/能标仅改标题、缺失段误连接、直方图分箱、谱线乱加点、图例样式错位等，并验证现行 XPS preparation 正确保留动能坐标。

独立审查后补上四类检查：实际后端采用的误差列必须逐值绑定 `uncertainty.source/display`，有定义及证据，不能把未声明误差交给后端就算核对；源表明确写动能而任务声明结合能时报告冲突，只有具体文件依据支持的 `source_energy_correction` 才可解释仪器模板标题错误；峰标/引线等尚未支持的施工字段明确要求交专用原生工具，不能静默忽略；类别横轴按显式 category 角色保留文本和顺序，矿物分类柱图等没有汇总 PPT 的普通项目可正常接入。

误差字段示例：`uncertainty` 包含 `definition: "SD"`、`evidence` 文件引用、`source` 与 `display` 的表/横坐标列/误差列绑定。现成 SD/SEM 数值按已有分析检查，不要求为一次标签移动补造 n。数值换单位时误差幅度只做有依据的正比例缩放，不随中心谱做纵向显示偏移。上下界型区间若超出当前适配，会明确停止转交专用路线。

仪器标题纠错字段给出 `header_kind`、`resolved_kind`、`reason` 与 `evidence`；这是绑定证据的例外，不是无条件相信或忽略原列名。未经这项说明，单把 KE 数值抄到 BE 列并改声明会被拦截。

能标冲突检查同时覆盖原表与显示表的英文全称、KE/BE 缩写、动能/结合能等中文名称，识别时统一大小写及括号、空格等格式差异。它采用现行 XPS 解析的明确名称词汇，不凭数值区间或单调性猜能标；`Energy (eV)`、未命名列等仍由已确认的来源身份和显式映射说明。带依据的标题纠正、实际坐标转换均保留。回归同时检验中英文别名冲突、未知名称、证据例外和真实转换进入准备计划。

标题可在明确名称前后带“原始采集”“校准后”等说明，不能因为多了说明就漏掉能标冲突。识别按完整词和单位/分隔边界处理，不把 `BEad`、`binding affinity` 等无关词看作结合能；同时写了两种能标的标题报告为歧义，需要证据解释。原表和显示表使用同一套词法检查。

已有工程独立重开成功后产生 `原生工程与导出绑定.json`，将当前 OPJU、各导出图、已反读源数组和图窗/工作表/曲线关系绑定起来，交付包可据此拒绝旧工程配新图。它只覆盖列明的曲线；没有完成独立反读的新表初次生产记录为 `NOT_PERFORMED`，不能据此宣布整个包一致。视觉检查和作者采用仍分别记录。

本机另以 501 点数学合成谱实际跑过正常真实表原生路线及已有工程局部修订。首次小画幅沿用旧图层导致横轴标题出界，原生门禁正确拦截；按实际尺寸调整图层后另存通过。新工程修改标题字号/曲线线宽后，以独立 Origin 进程重开，501 点真实 X/Y 绑定及所有保留工作表/矩阵一致；当前图与重开 PNG 逐像素相同。实际查看了导出图，合成窄谷完整，没有新遮挡。此范围不外推到所有模板、复杂分段绑定、陌生机器或作者科学/审美接受。真实论文原始数据和成品未作为写入测试材料。

独立审查后的原生复验还覆盖文本类别柱图和带 SD 列的点线图。类别文字及顺序正常，误差列按显式角色进入工程；点线图首次图例挡住右侧误差棒，实际查看后通过已有工程局部修订路线移开，再以独立进程重开。最终导出无该遮挡，修订前后全工作表（含误差列）一致，当前图与重开 PNG 逐像素相同。原生绑定证据覆盖本次声明的主曲线；误差附属图元并未另作独立图元绑定声明。未把自动核对、实际目视和整图任意科学正确性混成同一种通过。
