# 连续修订与作用范围

这一接口支持已有作品的连续修改，不要求每轮重建项目或填写大表。宿主根据作者现有指令生成最少记录；只移动一个已确认文字时无需追查整个实验。

## 本轮接入

`--module` 明确选择 plot、designer、vector 或 ppt。自然语言仍记录目的，但不再因“沿人工版修改并同步资料”缺少旧关键词而拒绝合理任务。设计阶段仅能进入 designer；只理解/审阅阶段不能调用生产。

有项目外输出、人工父本或冻结范围时，给 `--task-context 本轮.json`：

```json
{
  "schema_version": "task-context-0.1",
  "project_id": "example",
  "stage": "revise",
  "modules": ["ppt"],
  "parent": {"path": "人工采用.pptx", "sha256": "实际文件的SHA256"},
  "authorized_output_roots": ["新一轮"],
  "protected_paths": ["原始数据"],
  "delivery_modes": ["presentation"],
  "preferences": {"font_family": "Aptos"}
}
```

相对路径相对于该 JSON。Windows 自定义输出根在 D 盘，不能指定整个盘；实际路径解析后排除原件目录、人工父本及其祖先输出。子进程沿用同一上下文。输出仍为新文件/目录，父本变化则重新接入，不能用旧摘要覆盖人工保存。原有未使用上下文的工作台隔离输出保持兼容。上下文不是授权来源，宿主只能记录本轮用户已给的范围。

改备注、修当前SceneGraph或已有Origin时，实际被修改输入必须是声明的人工父本；不能声明一个正确父本却加工另一份旧稿。已核继承的派生稿可列入 `verified_descendants`，每项含 `artifact:{path,sha256}`、`adopted_parent:{path,sha256}` 和 `inheritance_review:{reviewer,evidence}`。这记录实际检查过的继承关系，不可用未经查看的口头“沿用”代替。

作者默认、项目设置、本轮例外可通过 `task_context.resolve_preferences` 合并，结果保留每个值的作用层次。没有提供的层不自动补齐。来源页、数据组、标注方式及其它项目设置由当前任务提供。

## 重排内容不能失去去向

`--check-revision 本轮核对.json --out 新核对目录` 调用 `revision_checks.check_request`。输入用已有小图ID延续，不用 a/b 或图号做身份：

```json
{
  "before": {"items": [{"id": "selection_A", "label": "4b", "source_id": "experiment_A", "groups": ["control", "material"], "annotations": ["rate"], "placement": "main"}]},
  "after": {"items": [{"id": "selection_A", "label": "R1", "source_id": "experiment_A", "groups": ["control", "material"], "annotations": ["rate"], "placement": "reserve"}]},
  "decisions": [{"id": "selection_A", "fields": ["placement"], "reason": "作者本轮要求保留为备用"}]
}
```

允许改变展示图号，不自动允许换来源、丢组别、漏数字或移动去向。删除/去重需 `action: omit/deduplicate` 及原因；新增需 `action: add` 且有合法去向。冻结条目设置 `frozen: true`，单处恢复修改需决定里的 `reopen_scope` 列出字段；删除必须显式包含 `omit` 或 `deduplicate`，不能用“只改字号”的解冻范围删整图。它核对已声明的内容，不自动识别图中所有实验；声明必须从实际父本核出。

## 审阅之后确实修改

同一请求可带 `findings`、`fixes`、`rechecks`。三类记录共用问题 `id`。

- 发现：`location` 指具体页/对象，`artifact`、`sha256` 绑定当时看见问题的文件版本；能读取具体对象指纹时再带 `object_digest`。待作者确认时写 `disposition: needs_author`、`question`、`source_location`。
- 修复：`artifact` 指改后文件，`sha256` 对应实际保存，保留处理说明。
- 复验：`sha256` 指本次查看的版本，`result: PASS`、`reviewer` 和 `evidence` 写实际复验方式与结果。

只收到审阅报告仍为 OPEN；改了但未复验为 FIXED_PENDING_RECHECK；文件又变化则为 STALE_FIX。改后文件与发现时相同会返回 UNCHANGED；绑定了具体对象但只改其它地方为 UNCHANGED_OBJECT；缺发现版本则为 CHANGE_NOT_VERIFIED，不能登记已实际修改。只有对应当前文件及确有改变的复验记录才能 CLOSED。这证明记录没有脱节，不证明审美/科学事实由程序自动评判。

若实际导出证明原报告误判、无需改动，可在修复处明确 `resolution: no_change_required` 及 `reason`，复验也要明确同一resolution、当前文件哈希、reviewer和evidence；结果为 CLOSED_NO_CHANGE_REQUIRED，不能冒称已修改。未处理的实质问题继续修；新增问题可以加入，不以“上一轮已通过”或固定轮数免检。

## 显微图沿用的是实际显示

`--inspect-microscopy 请求.json --out 新目录`，请求含 `pptx` 和可选 `pages`（原文件从1开始）。记录原页对象、媒体、裁剪、旋转/镜像、亮度/对比及组合变换。媒体像素相同不等于继承了汇总 PPT 已处理的显示；实际渲染仍需对照。只读提取不改实验像素。

`microscopy_sources.compare_displays` 可比较来源记录，挪位使用 `translate`，等比缩放使用 `uniform_scale`，镜像和旋转分别使用 `flip`、`rotation`；组变换用对应 `group_` 前缀。不允许笼统放开 transform 让镜像和非等比拉伸混入移动操作。显示颜色处理和裁剪仍分别核对。`scale_bar_check` 用仪器标定、源裁剪宽度、当前图宽和尺长换算；整体等比放大图和尺不会被判错。返回 CHECK_CALIBRATION 是核对线索，不能直接写成原汇总错误。
