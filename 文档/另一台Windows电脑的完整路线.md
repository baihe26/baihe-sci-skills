# 另一台Windows电脑的完整路线

**0.5起优先使用[公开配套与自动安装](0.5公开配套与自动安装.md)**：完整下载仓库、解压到D盘，运行根目录安装入口即可自动准备独立环境。下面保留0.4时代的个人迁移方法，描述的是旧版分发范围，不是0.5的限制。

GitHub普通下载只含五个技能、共享工作台和受支持的可选后端。安装Office、Illustrator、Origin与取得本系列配套程序是两件事。`--doctor`缺少配套路径时，不应重复安装五个SKILL.md或用简单后端冒充完整路线。

## 原作者迁移到自己的另一台电脑

在已有原生引擎且已配置的原电脑上，可以用`工作台/源码/migration_pack.py`按明确白名单整理个人配套副本。新输出必须在D盘，不覆盖旧引擎，不复制科研资料、实验项目、历史工程、软件环境或凭据。`--include-python`可带入已验证版本的Python标准运行时副本，明确排除原环境site-packages；依赖须在该私有副本内重新准备，不能把原venv整体搬走。

```text
python 工作台/源码/migration_pack.py --config baihe-sci.local.json --out 工作台/产物/我的个人迁移包 --include-python
```

这个构建入口先整理源码和标准运行时，**不会仅凭文件齐全就宣称依赖、原生软件或新电脑已经可用**。随后按新副本实际依赖准备独立运行时、保存依赖锁与许可、刷新文件清单，并验证重定位。完整配置入口需最终个人包中有`Python/python.exe`及兼容依赖；本构建命令本身不联网、不安装共享环境或改全局设置。

完整个人包的使用方法：将整个包完整解压到目标电脑D盘的新目录，运行`配置与检查.cmd`，再让目标机Codex读取`从这里开始.md`和配置结果。使用包内`启动工作台.cmd`选择新路径，不覆盖原下载仓库或全局技能。已有的五个技能可以保留。

## 配套与验证边界

- 包括实际依赖的工位/模板/科学合同、冻结Designer重放与schema、Illustrator桥接与导出审计、Live Studio及固定PPT后端、已批准作者样式。只在副本做明确记录的路径兼容，不改原冻结引擎和科学规则。
- 原生应用、许可证、系统字体、硬件、个人科研数据及正式成果不随包迁移。旧诊断工程和历史验收不作为新电脑已通过的证明。
- 当前Origin worker仍保留Python 3.12.10、OriginPro 2026 SR0 x64 build 180的既有门禁；目标版本不同须单独查证兼容。不能删除门禁，也不能因此阻断设计、Illustrator和PPT等独立模块。
- 文件/依赖检查、应用可用性、合成例实际生产/重开/编辑、整页视觉、作者接受分开。配置脚本不自动启动软件或制作正式科研图。
- 个人迁移包包含未随公开仓库分发的原作者工具，不自动上传GitHub。第三方许可随对应源码/依赖保留，不能将“公开可读”解释为任意软件或素材均可再分发。

维护方应把私有迁移产物放在被忽略的输出目录；不可提交本机配置、运行时、引擎副本或ZIP。新迁移仅核验本次改变涉及的路径/接口，不无理由重跑未受影响的全套旧原生案例。
