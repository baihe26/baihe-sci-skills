# 示意图与矢量的连续修订

这轮将实际返工中的四类问题落到代码：显示修订不能移动对象；修订轮数和新问题被机械拦住；假说只能虚线；渐变、透明和连续纤维在简单后端丢失。现有来源绑定、原生独立重开、人工冲突、像素保留和跨副本单写者继续沿用。

## 1. 三种入口各负其责

- 忠实重建：先识别可见内容、保留实验像素，未知不补猜。
- 批准场景施工：来源、主张、关系通过一致性检查后输出，保留科学侧件。
- 人工父本局部修订：现有PPT简单文字、字体、字号和位置修改直接用`--edit-ppt`，不重建全套图件。既有COM的`ppt_adapter.local_edit`改字、移动、颜色保留；已有SceneGraph用`refinement.revise`。高级AI原生对象仍走已安装的桥接与原工程。尚未实现任意现有AI的统一批量修订接口，不能宣称全自动支持。

现有用户授权决定可改范围。某材料的颜色、某配方的选择、某页的字号或应用场景属于项目事实/作者选择，不随技能推广到其它项目。

### 现有PPT的小修改

先用`ppt_local_patch.inspect_ppt(path)`读取实际对象ID、文字、run、坐标和哈希。随后给`ppt_local_patch.edit_ppt(request_path,out)`或`baihe-sci.cmd --edit-ppt <请求.json> --out <新目录>`如下请求：

```json
{"schema_version":"ppt-local-patch-0.1",
 "source":{"path":"人工父本.pptx","sha256":"当前文件哈希"},
 "changes":[
   {"slide_number":1,"shape_id":2,"fields":{"text":"Hydrogel characterization","font_name":"Calibri","font_pt":22}},
   {"slide_number":2,"shape_id":5,"fields":{"position_pt":[46,161]}}
 ]}
```

数字、文字和字体只是脱敏测试例，必须换成本次任务的实际对象和要求。对象还可写`expected_object_sha256`，增加指定对象的前提核对。`position_pt`为幻灯片坐标，`move_pt`为相对位移；普通缩放组可换算，旋转/翻转的祖先组转原生处理，不能猜位置。

单run文字替换保留其粗体、颜色、上下标、链接等其它格式；所选对象未指定字体或字号时不改这些值。多段、多run、域或显式换行不压平，须用`runs:[{paragraph_index:1,run_index:2,expected_text:"原字",text:"新字"}]`逐项改，必要时每run单独给字体/字号。

`font_name`表示将所选run的拉丁、东亚和复杂文字三类字体都设为该名称，中文已有微软雅黑时要求改等线也会实际改东亚字体。只需改某个脚本时用`font_latin`、`font_east_asian`或`font_complex_script`；这些字段不能与同次`font_name`混用，以免含义冲突。修改某脚本不会改另两个脚本；其它run、粗体、颜色、上下标、超链接和符号字库保持原样。回执逐run列出实际写入的字体域；字体是否安装及软件最终替代情况仍须原生导出/读回核验。

接口核验当前人工父本和源哈希，不改原件；新PPT仅重写被选页的XML，并比较该页未选对象，所有其它页面、备注、媒体、嵌入原工程和关系部件保留原始字节。保存包检查不代表应用内未保存内容已观察，也不代替最终软件实际渲染。此小修改无需FigureSpec、ConstructionPlan、scientific_binding或新设计审批。

若同时使用任务上下文，其模块范围写 `modules: ["local"]`；`--edit-ppt` 不与 `--module` 混用。只读阶段拒绝编辑，授权局部修改仍另存新副本。

## 2. 有进展的连续修改

`refinement.revise(scene_path, request_path, out)`保持旧字段兼容：父本SHA、整包指纹、绑定当前成品的审阅、对象范围和具体修改仍必需。新输出目录不能覆盖父本。

新增`fields`：

|字段|范围与限制|
|---|---|
|`translate_px: [dx,dy]`|移动矩形、椭圆、文字或折线；不改文字/样品身份。任意SVG路径移动仍走原生路线|
|`bbox_px: [left,top,right,bottom]`|调整示意矩形/椭圆；不能拿它改变实验图像纵横比|
|`points_px: [[x,y],…]`|调整折线和关系路由；同步FigureSpec路线、ConstructionPlan及SceneGraph；关系源、目标、确定性不变|
|`z_order`|整数层级，需在当前审阅对象范围内；最终须检查遮挡|
|`opacity`|0到1之间且不为0；审阅`presentation_permissions`须明确该对象、字段和理由，防止隐去科学对象|

原有填色、描边、线宽、字号继续可用。字号更新同时写入SceneGraph的几何和原生文字字段。

空间修订会更新受影响的组边界。箭头端点必须仍接近所指实体，不能维持关系ID却指到另一材料。默认允许已有间隙或实体对角线十分之一的局部间隙；更大间隙可在请求的`relation_endpoint_review`中逐箭头写明source_id、target_id、reason及source_maximum_gap_px/target_maximum_gap_px。这个几何保护不是规定箭头必须贴边，也不是科学正确性证明。最终图上的实际指代仍需审阅。

示例修改项：

```json
{"object_id":"AI_label_A","fields":{"translate_px":[0,8]}}
```

`max_rounds`默认不设上限。用户指定预算时保留正整数预算；后续明确更新预算可继续。新审阅发现不要求是旧问题集的严格子集。相同问题若进行了有效修改可继续，无实际内容变化则拦截空转。`processing_ledger.bounded_review`只是建议：持续没有新证据应换方法；不能把“改方法”或“预算用完”说成任务完成。

## 3. 假说的线型与证据级别分开

旧包继续要求其既定虚线。新包若需要实线，可在`scientific_binding.certainty_disclosures`写明对应关系的工作模型说明，并绑定可见文字或随图交付的真实图注：

```json
{"relation_ids":["R2"],"evidence_level":"HYPOTHESIZED",
 "location":"legend","object_id":"AI_model_note",
 "text":"Proposed working model"}
```

`title`、`legend`、`caption_object`要求该TEXT对象确实存在且文字完全一致。`caption_file`使用`source:{path,sha256}`及文件中存在的text；该文件纳入复制、指纹和父本保护。

声明不能改变claim、relation、binding的证据级别、方向、否定或因果关系。程序仅核对实际文字与身份。说明是否充分、是否随最终图交付，由当前成品审阅确认，仍不能由模板认定具体异质结模型。

## 4. 一致换色而不换样品

已有`color_roles.json`继续约束科学色。显示请求可新增`color_reencoding`：

```json
[{"role":"material_A","from":"#477E9D","to":"#255FC7",
  "scope":"current_scene","authorization":"作者要求在当前图统一提高该材料的颜色区分度。"}]
```

该role应表示可独立编码的具体身份/条件。请求的`changes`必须包含所有受绑定的对象和legend_object_ids，且全部改为相同新色；漏一项不能通过。新输出更新角色侧件，父本不变。仅当前场景完整不证明全文已同步，其它图仍由交付范围核对。

实验通道或测量伪彩使用`encoding_domain: microscopy_channel / measured_pseudocolor`或`protected_channel: true`，不能经普通显示重编码改色。未知颜色语义仍需原有装饰色证据，不能随意放行。

## 5. 渐变、透明与可编辑曲线

ConstructionPlan元素可使用`opacity`和`fill_gradient`。关系的`style`可以声明stroke、stroke_width、opacity。适配层恢复这些字段，不修改冻结编译器历史源码。

```json
{"opacity":0.65,"fill_gradient":{"kind":"linear","angle_deg":25,
 "stops":[{"offset":0,"color":"#EFFAFF"},{"offset":1,"color":"#237795"}]}}
```

径向渐变使用`kind: radial`及可选`center:[0.5,0.5]`。stops至少两个，严格递增，首尾为0和1；每个停点可有opacity。未知字段、非法颜色或非有限数不会被默默忽略。旧schema在本地严格投影，只移除已独立验证的fill_gradient扩展；其它未知字段仍失败。

|后端|本轮实际代码覆盖|
|---|---|
|SVG / Illustrator适配|原有RECT、ELLIPSE、POLYLINE、PATH和TEXT；渐变定义、透明、关系线宽传递到SVG。Illustrator原生导入效果仍按本机实测验收|
|portable PPT|上述普通形状，保留图像，线性/径向渐变、透明；PATH支持绝对M/L/C/Q/Z并写原生贝塞尔控制点，不将曲线采样成位图|
|原生PPT简单适配|原有普通形状、文字、关系，加透明。渐变和PATH在此路线给出明确转交，不隐去效果|

`design_styles.capability_route(graph, requested, retained_assets)`只读给出当前所需能力、缺项和可用替代后端。不能把这个结果当作已经生产。复杂资产引用、任意clip、其它SVG命令等能力缺口仍应使用成熟原生工程，不能为使用统一薄入口而降低画质。

实际渲染发现，旧轻量预览器会把渐变变成黑色并丢掉虚线，不能只凭SVG/XML有字段认定效果正常。当前生成的自包含SVG优先用本地Chromium渲染，使用工作盘隔离配置，不接触用户浏览器会话、不接远程服务。没有兼容渲染器时保留SVG并报告所缺能力，不生成失真的PNG冒充预览。纯SVG序列化不再导入PDF渲染器或整个冻结引擎。

## 6. 验证范围

`tests/test_design_regressions.py`以脱敏合成素材验证：

- 移标签而不改标签内容、原始父本或无关关系。
- 箭头改路由同步侧件，错误指向另一实体失败。
- 七轮连续有效修改和新问题继续，明确预算与无改动保护保留。
- 实线假说需要存在且绑定的可见说明，图注变化使指纹失效。
- 科学角色换色必须覆盖全部图例，原通道保护不降级。
- 渐变/透明保留到SVG和保存后的PPTX，曲线路径保留原生控制点。
- 不支持的功能明确转交，不自动栅格化。

这些检查证明约定范围内的数据结构、文件内容和保护逻辑。Office/Illustrator实际打开、编辑和视觉效果另记实测，合成案例不能代表所有真实论文图，也不替代作者审美采用。

本轮另对一页脱敏合成纤维/透明层/局部球体图完成了本机PowerPoint实际打开、导出PNG、另存、独立重开、原生文字修改及读回；并在非交付副本中修改一条贝塞尔曲线的节点和一个渐变停点颜色，保存重开后读回一致，输入文件未改变。实际PNG中渐变、连续曲线、可辨小球、透明层及虚线保留。这个结果仅覆盖该一页、本机PowerPoint与这些操作；Illustrator新增渐变的导入/编辑、任意复杂clip和作者最终采用尚未验证。私有运行产物留工作区，不随公共源码打包。

独立复验另外发现通用字体字段此前只改了拉丁字库，会留下旧的东亚字体。修复后用审阅者原始合成中文PPT及原请求实际复跑：PowerPoint修改前/保存重开均读回东亚字体“微软雅黑”，修改后/保存重开均读回“等线”，文字和18 pt字号保持原值，原输入哈希不变，输出PNG也显示对应字形变化。逐run脚本字体与上下标保护另有自动回归；这个原生结果只覆盖该例及本机已安装字库，不保证任意未安装字体的系统替代结果。
