# 0.6升级与使用

日期：2026-10-22。本次源码版本为0.6.0。原始科研数据、已有图件/PPT、selected B、V03、冻结Designer与底层引擎保持原样。

## 日常怎么用

继续在完整仓库中向Codex说自然语言。它应替你整理必要短清单；只有缺少会改变科学含义的事实才问，不要求你手写JSON或内部ID。

- “先盘点这几个明确文件，哪些能直接排图、还缺什么，不做统计。” → 只读项目接入。
- “把这四张已选图按论文栏宽给两个panel方案，图区对齐，不改图和组色。” → 物理尺寸布局候选。
- “最后的PPT检查这些字、箭头端点和原生对象是否兑现，不要只看截图。” → 保存文件目标核对；真实编辑动作另验。
- “只改背景对比度，保留材料身份色。” → 已绑定评审的装饰色修订；科学色不按display-only处理。

面板候选只提供位置、源区域、字号提示与线框SVG，不是最终科研排图或自动施工。未确认项目事实、原生编辑、视觉和作者接受继续保留待审。单模块调用、真实数据工位与原生AI/PPT路线均保留。

## 程序入口

下面的文件由宿主从你的明确任务和来源生成，供维护或复现使用：

```text
baihe-sci.cmd --doctor
baihe-sci.cmd --inspect-project <接入清单.json> --out <新目录>
baihe-sci.cmd --plan-panels <接入清单.json> --out <新目录>
baihe-sci.cmd --verify-delivery <目标清单.json> --artifact <最终PPTX> --out <新目录>
```

只读接入清单使用`project-intake-0.1`：project_id；sources中的id/path/kind及可选已知科学字段；panels中的id/source_id。图号覆盖可给required_figure_ids和figure_uses；每项给placements或unused_reason，择一。数值数据缺experimental_unit/statistical_n/uncertainty/units/denominator/design时列待核对，不补值。

任何来源（包括已选图片）明确给出的UNKNOWN/HOLD/CONFLICT或待核对科学字段都会单列；图片不会被强迫补齐数值数据的整套字段。review_reason可说明HOLD原因。来源选择CONFIRMED与科学字段尚未确认可同时存在，不能互相覆盖。

布局另给canvas_mm、layout_columns、可选margin_mm/gap_mm/label_band_mm/minimum_font_pt。panel可给source_box_px、plot_area_normalized、source_font_pt/source_width_mm；没有文字尺寸就保留NOT_RECORDED。共裁只有明确crop_group/frame_id时检查一致；channel/timepoint等随panel记录，不推断采集身份。calibration包含pixels_per_um及有哈希的来源；不自动生成比例尺。当前候选输入支持无旋转PNG/JPEG，其他格式交已有原生路线。

`color_roles.json`使用`color-roles-0.1`，bindings逐项给object_id、field（fill/stroke）、kind（decorative/scientific）、reason；scientific还给role/value，可给legend_object_ids。无侧件的旧包改色，review中须有decorative_color_permissions，逐项说明object_id、fields和reason，仍受父版本/整包哈希、finding和对象范围约束。真正科学重编码不得伪装成该声明。

`style_profile.json`使用`style-profile-0.1`：profile_id/version/scope/source(path,sha256)；overrides逐条给rule/scope/reason/authorization_source(path,sha256)。个人文件和授权留本机，不进入公开示例。此侧件不应用主题；宿主仍须遵循已有作者风格。

`delivery_requirements.json`使用`delivery-requirements-0.1`：observations逐项给id/object_id/kind/expected，可指定slide_index（从1开始）。kind可为text_equals、fill_equals、native_type、connector_targets、min_font_pt、edit_action。connector_targets的expected为begin/end对象名；edit_action描述需实际验证的动作，文件回读永远不能替它给PASS。科学图包中的文字/颜色期待必须与批准Scene一致。

上述三个侧件进入依赖指纹和Designer复制交接。单页portable及原生PPT矢量生产发现最终目标侧件时自动回读并输出报告；硬目标FAIL就停止宣称完成。独立`--verify-delivery`也可核对后处理的最终文件；结构检查依赖已有python-pptx，不启动Office。

保留位图可增加semantic_content：allowed_content、forbidden_content、native_surrounding_ids。程序核对字段和外围对象身份；像素里是否夹带不该保留的文字/箭头仍要视觉审核，不能把声明当识别结果。

## 如何用于已有论文排图项目

先由项目对话读取已确认project_id的当前状态和授权来源。复用已认可图件，按逻辑Figure/panel身份接入；清单记录图面/图注分别承载的信息，未确认n、分母、通道、标定或来源HOLD。只比较构图与最终宽度；数据组色、荧光LUT和PPT品牌色分开。现有图放不下时拆panel/页或另做显示副本，不通过改数值或缩到不可读来挤满。

候选确认后，宿主用已有Illustrator/PPT生产链施工，保留来源、原生工程和编辑级别。最后对所选文件做目标核对、原生重开/实际编辑和整图视觉检查。此流程不自动处理原始显微图或重新统计，不补造缺失图件。
